# 322 · 零钱兑换

<ProblemMeta id="322" difficulty="中等" title="零钱兑换" :tags="['完全背包', '状态定义', '不可达标记']" url="https://leetcode.cn/problems/coin-change/" />

::: cheat 速查卡
- **什么时候用**：求"凑出目标值的最少个数"，物品可重复使用
- **核心不变式**：`dp[i]` 表示凑出金额 `i` 的**最少硬币数**，`dp[i] == INF` 表示凑不出
- **一句话模板**：完全背包，容量正序，`dp[i] = min(dp[i], dp[i-c] + 1)`
- **复杂度**：时间 **O(amount × n)**、空间 **O(amount)**
:::

## 题意重述

给定硬币面值数组 `coins` 和目标金额 `amount`，求凑出该金额的**最少硬币枚数**。每种硬币**无限个**。凑不出返回 `-1`。

```
输入: coins = [1, 2, 5], amount = 11
输出: 3        ← 5 + 5 + 1

输入: coins = [2], amount = 3
输出: -1       ← 永远凑不出奇数

输入: coins = [1], amount = 0
输出: 0        ← 不需要任何硬币
```

三个例子的重点各不相同：

1. 第一个是"有解"，且要证明 3 是最优
2. 第二个是**不可达**，必须返回 `-1` 而不是 `0` 或 `INF`
3. 第三个是**边界**：金额 0 的答案是 0，这是递推的起点

## 从朴素到 DP

朴素想法：暴力枚举每种硬币用几枚。`[1,2,5]` 凑 11 时，`5` 最多用 2 枚、`2` 最多 5 枚……组合数爆炸。

关键观察：**凑出金额 `i` 的问题，和凑出更小金额的问题是同一类问题。**

凑 11 的最后一步，必然是用了某个面值 `c` 的硬币，剩下的 `11 - c` 仍然要"最少硬币数"凑出来。这就是**最优子结构**：

```
dp[11] = min(dp[11-1], dp[11-2], dp[11-5]) + 1
       = min(dp[10],  dp[9],   dp[6])   + 1
```

注意这个递推里**没有任何"用了多少枚某种硬币"的信息** —— 有也没关系，因为我们只关心总数最小。

## 模板对照

::: compare
```cpp
// 完全背包通用骨架：物品可重复，容量正序
vector<int> dp(capacity + 1, INF);
dp[0] = 0;
for (int i = 1; i <= capacity; ++i) {           // 外层：容量
    for (int c : items) {                       // 内层：物品
        if (c > i) continue;
        dp[i] = min(dp[i], dp[i - c] + cost);
    }
}
```
```cpp
// 本题：cost 恒为 1，INF 用 amount+1
vector<int> dp(amount + 1, amount + 1);   // 哨兵
dp[0] = 0;                                // 唯一确定的起点
for (int i = 1; i <= amount; ++i) {
    for (int c : coins) {
        if (c > i) continue;              // 面值超过目标，跳过
        dp[i] = min(dp[i], dp[i - c] + 1);
    }
}
return dp[amount] > amount ? -1 : dp[amount];
```
:::

三个决策点：**哨兵值**、**循环顺序**、**返回时的判断**。

### 哨兵为什么是 `amount + 1`

安全上界：凑出 `amount` 最多需要 `amount` 枚硬币（全用面值 1）。所以任何**真实**答案都 `<= amount`。用 `amount + 1` 当"无穷大"：

- 不会溢出（`amount + 1 + 1` 远小于 `INT_MAX`）
- 便于最后判断：`dp[amount] > amount` 就一定不可达

对比 `INT_MAX`：

```cpp
dp[i] = min(dp[i], dp[i - c] + 1);   // dp[i-c] == INT_MAX 时，+1 溢出成负数
```

`INT_MAX + 1` 是有符号溢出，**未定义行为**。虽然实际大多变成 `INT_MIN`，`min` 恰好不会选中它，但这是运气不是设计。

::: danger 易错
用 `INT_MAX` 当哨兵时，如果转移写成 `dp[i] = min(dp[i], dp[i-c] + 1)` 而不判 `dp[i-c] != INT_MAX`，**这是 UB**。在开启 `-ftrapv` 或某些优化级别下会出问题，OJ 上偶发 RE。

用 `amount + 1` 这类具体值就完全没这个隐患。
:::

### 循环顺序：外层容量、内层物品

本专题的[完全背包讨论](/topics/dp/#遍历顺序)里说过：容量**正序**是"物品可重复使用"的关键。

但还有一层：**外层和内层谁在外面，影响的是"求什么"**。

| 外层 / 内层 | 表达的含义 | 适用 |
|---|---|---|
| 容量 / 物品 | 每个金额独立地挑最优 | 求**最少个数**、最少花费（本题） |
| 物品 / 容量 | 按物品顺序决策 | 求**方案数**、组合数（518 零钱兑换 II） |

本题求"最少个数"，两种顺序结果相同（因为 `min` 与顺序无关）。但 518 求**方案数**时，顺序不能乱：

- 物品在外 → 硬币 `1,2` 和 `2,1` 算**同一种**（组合数）
- 容量在外 → 算成**两种不同**（排列数）

::: warning 坑点
322（最少个数）和 518（组合数）看起来是同一题，但**循环顺序一个可以换、一个绝对不能换**。写完 322 直接抄去写 518 会 WA。
:::

## 完整可编译代码

```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        if (amount == 0) return 0;                    // 边界：0 元不需要硬币

        // dp[i] = 凑出金额 i 的最少硬币数
        // amount + 1 是安全哨兵：真实答案不可能超过 amount
        const int INF = amount + 1;
        vector<int> dp(amount + 1, INF);
        dp[0] = 0;                                    // 起点：凑 0 元要 0 枚

        for (int i = 1; i <= amount; ++i) {           // 容量正序 = 完全背包
            for (int coin : coins) {
                if (coin > i) continue;               // 面值超过目标金额
                // dp[i-coin] 若仍为 INF，INF+1 > INF，min 不会选中它
                dp[i] = min(dp[i], dp[i - coin] + 1);
            }
        }

        return dp[amount] > amount ? -1 : dp[amount];
    }
};

int main() {
    Solution sol;

    {
        vector<int> coins{1, 2, 5};
        assert(sol.coinChange(coins, 11) == 3);       // 5+5+1
    }
    {
        vector<int> coins{2};
        assert(sol.coinChange(coins, 3) == -1);       // 不可达
    }
    {
        vector<int> coins{1};
        assert(sol.coinChange(coins, 0) == 0);        // 边界：0
    }
    {
        vector<int> coins{2};
        assert(sol.coinChange(coins, 0) == 0);        // 边界：0（和面值无关）
    }
    {
        vector<int> coins{1};
        assert(sol.coinChange(coins, 100) == 100);    // 全用 1
    }
    {
        vector<int> coins{186, 419, 83, 408};
        assert(sol.coinChange(coins, 6249) == 20);    // 力扣官方大用例
    }
    {
        vector<int> coins{5};
        assert(sol.coinChange(coins, 3) == -1);       // 面值大于目标
    }
    {
        vector<int> coins{1, 2147483647};
        assert(sol.coinChange(coins, 2) == 2);        // 极大面值不应溢出
    }

    cout << "all tests passed" << endl;
    return 0;
}
```

最后两个用例值得注意：

- `coins = [5], amount = 3`：所有面值都大于目标，内层全 `continue`，`dp[3]` 保持 `INF`，返回 `-1`
- `coins` 含 `INT_MAX` 类面值时，如果拿 `dp[amount] + 1` 或 `coin + something` 去算，很容易溢出。用 `amount + 1` 哨兵 + `coin > i` 提前跳过，天然规避

## 逐段拆解

::: semantics
| 字段 | 含义 | 在代码里怎么用 |
| --- | --- | --- |
| `dp[i]` | 凑出金额 `i` 的**最少硬币数**；`INF` 表示凑不出 | 下标是**金额**，不是物品序号 —— 这是本题状态定义的核心 |
| `INF = amount + 1` | 安全无穷大 | 比任何真实答案大，且不会在 `+1` 时溢出 |
| `dp[0] = 0` | 凑 0 元要 0 枚 | 唯一确定的起点，其余全靠递推 |
| `i` | 当前要凑的金额 | 从 1 到 `amount`，**正序** |
| `coin` | 试用的最后一枚硬币面值 | 内层循环，顺序无关（只是 `min`） |
| `dp[i - coin] + 1` | 用了这枚硬币后，剩下的最少枚数 + 这 1 枚 | `+1` 是"用掉一枚"的代价 |
| `dp[amount] > amount` | 不可达判定 | 因为真实答案 `<= amount` |
:::

### 状态定义为什么用"金额"做下标

三个候选：

| 定义 | 能否写出转移 |
|---|---|
| `dp[i]` = 用前 `i` 种硬币凑出 `amount` 的最少数 | 需要额外维度记录"当前金额" → 二维 |
| `dp[i]` = 凑出金额 `i` 的最少数 | ✅ 一维搞定 |
| `dp[i]` = 用恰好 `i` 枚硬币能凑出的金额集合 | 状态爆炸 |

第二种之所以可行，是因为**金额本身就是"进度"**。凑出 11 的进度，就是"已经凑了多少钱"，不需要额外记录用了哪几种硬币。

这也是 DP 状态设计的通用技巧：**找那个"随着过程单调推进的量"，用它当下标。** 这里是金额，在背包问题里是容量，在字符串问题里是长度。

### `+1` 的位置

```cpp
dp[i] = min(dp[i], dp[i - coin] + 1);
```

写成 `dp[i] = min(dp[i], dp[i - coin]) + 1` 是**错的**：

- 前者：对每个 `coin` 尝试"用一枚"，取所有方案的最小值
- 后者：先取 `dp[i-coin]` 的最小值，再加 1 —— 但 `min` 是在循环内做的话，`dp[i]` 会被反复 `+1`

具体说，`dp[i]` 初始是 `INF`，第一次循环后变成 `INF + 1`，第二次又 `+1`…… 结果随 `coins.size()` 增长。**`+1` 必须在 `min` 的参数里，跟着单次决策走。**

### 为什么内层 `coin` 顺序无所谓

`min` 满足交换律和结合律，`dp[i] = min(dp[i], dp[i-c1]+1, dp[i-c2]+1, ...)` 与 `c` 的遍历顺序无关。

但**这个自由只在求 `min`/`max` 时成立**。求方案数时是累加（`+=`），顺序会改变计数语义，见上面的坑点。

## 坑点

::: warning 坑点
1. **不可达返回 0**：`dp[amount] == INF` 时直接 `return dp[amount]` 会返回 `amount+1`，题目要 `-1`。必须显式判断。

2. **`amount == 0` 的特判**：其实 `dp[0] = 0` 已经处理了，`amount == 0` 时循环不进、直接返回 0。但显式写 `if (amount == 0) return 0;` 更清晰，也能防 `dp` 构造时的边界问题。

3. **`INF` 用 `INT_MAX`**：`dp[i-coin] + 1` 溢出，UB。

4. **`coin > i` 忘记跳过**：`dp[i - coin]` 下标为负 → 越界。虽然 `dp` 的 `operator[]` 不做检查，但读到的垃圾值会污染 `min`。

5. **以为"硬币面值有 1 就一定有解"**：不一定，`[2,3]` 凑 1 就无解。不要做这种优化。
:::

::: info 补充
这题是"完全背包求最小价值"的标准形态。同一套模板换个 `cost` 就能解：

| 题 | `dp[i]` 含义 | `cost` |
|---|---|---|
| 322 零钱兑换 | 最少硬币数 | 1 |
| 279 完全平方数 | 最少平方数个数 | 1 |
| 377 组合总和 IV | 方案数（排列） | —— 用 `+=` |
| 518 零钱兑换 II | 方案数（组合） | —— 用 `+=`，且物品在外层 |

**模板相同，语义全在 `dp` 定义和 `min`/`+=` 的选择上。**
:::

## 变体与练习

| 变化 | 改什么 |
|---|---|
| 每种硬币只能用一次（0-1 背包） | 容量**倒序**遍历 |
| 求方案数（518） | `dp[0] = 1`，`dp[i] += dp[i-c]`，**物品在外层** |
| 求方案数且顺序有关（377） | `dp[0] = 1`，`dp[i] += dp[i-c]`，**容量在外层** |
| 要求输出具体方案 | 额外记录 `choice[i]`，最后回溯 |
| 硬币数量有限 | 变成多重背包，需要额外维度或二进制拆分 |

::: details 为什么 322 的 `dp` 不用二维？

因为**物品可以无限使用**，所以"用了哪些物品"不需要限制 —— 任何组合都合法。既然没有约束，就不需要那个维度。

反过来，如果每种硬币只能用一次，就必须加一维记录"考虑到第几种硬币"，或者在压缩后用倒序模拟。

**维度的数量 = 需要考虑的约束数量。** 没有约束的维度可以直接省掉。
:::

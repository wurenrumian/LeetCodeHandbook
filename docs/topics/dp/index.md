# 动态规划 · 模板与变体

DP 的题看起来千变万化，但落到代码上只有四个东西：**状态定义、状态转移、初始化、遍历顺序**。四者缺一，或者彼此矛盾，就会写出"能跑但答案不对"的代码。

本文只讲一件事：**怎么把一道题的题意翻译成这四个部分**。

## 第一步永远是定义状态

DP 卡住的时候，99% 是状态没定义清楚。判断一个状态定义好不好，看两个标准：

1. **能不能表达"答案"**：最终答案要能从某个 `dp` 值直接读出，或简单组合得到
2. **能不能写出转移**：`dp[i]` 能不能只用更小规模的状态算出来

::: warning 坑点
同一个变量名 `dp[i]`，在不同题里可能完全不是一个意思：

| 题 | `dp[i]` 的含义 |
|---|---|
| 322 零钱兑换 | 凑出金额 `i` 的**最少硬币数** |
| 70 爬楼梯 | 爬到第 `i` 阶的**方案数** |
| 300 最长递增子序列 | 以 `nums[i]` **结尾**的最长长度 |
| 1143 最长公共子序列 | `text1[0..i)` 和 `text2[0..j)` 的最长公共长度 |

所以**读题解时先看状态定义，别急着看转移方程**。同一个方程在不同定义下含义完全不同。
:::

### 定义状态的三个套路

| 套路 | 形态 | 适用 |
|---|---|---|
| 前缀型 | `dp[i]` = 考虑前 `i` 个元素 | 序列、字符串、背包 |
| 区间型 | `dp[i][j]` = 区间 `[i, j]` 的答案 | 回文、合并石子、戳气球 |
| 结尾型 | `dp[i]` = **以 `i` 结尾**的答案 | 子序列类（300、53） |

"前缀型"和"结尾型"最容易混：

- 前缀型：答案是 `dp[n]`（最后一个状态的**累积**结果）
- 结尾型：答案是 `max(dp[i]) for all i`（因为**不以 `i` 结尾**的子序列可能更长）

300 最长递增子序列如果写成前缀型 `dp[i] = 前 i 个里最长的`，转移写不出来 —— 因为不知道新元素能不能接上，必须记住"上一个选了谁"。这就是为什么要用结尾型。

## 状态转移

转移方程来自**最后一次决策**。问自己：到达 `dp[i]` 的最后一步，有哪几种可能？

拿 322 零钱兑换举例：

> 凑出金额 `i`，最后一枚硬币可以是 `coins` 里的任意一个 `coin`（要求 `coin <= i`）。
> 用了它之后，剩下要凑 `i - coin`。
> 所以：`dp[i] = min(dp[i - coin] + 1) for all coin`。

**"最后一步"分析法**适用于绝大多数 DP。它的产物是一句带 `for` 的话，翻译成代码就是转移方程。

## 初始化

初始化的作用是**给递推提供起点**，同时**表示"不可达"**。

这是 DP 里最容易静默出错的地方，因为"不可达"和"答案是 0"经常用同一个值表示。

::: danger 易错
求最小值时用 `0` 表示"不可达"是灾难性的：

```cpp
vector<int> dp(amount + 1, 0);    // 错！
dp[i] = min(dp[i], dp[i - coin] + 1);
// dp[i - coin] == 0 会被当成"凑出 i-coin 需要 0 枚"，于是 dp[i] 被算成 1
```

正确的做法是用一个**显然不可能的值**当哨兵，并且**按哨兵的种类决定要不要判可达**：

- `INT_MAX`：必须判 `if (dp[i - coin] != INF)`，否则 `INT_MAX + 1` 是有符号溢出（UB）
- `amount + 1`：**不用判**，`INF + 1 > INF`，`min` 天然不选它
:::

| 求什么 | 初始化 | 不可达标记 |
|---|---|---|
| 最少数量 | `dp[0] = 0`，其余 `INF` | `INF`（如 `amount + 1`） |
| 方案数 | `dp[0] = 1`，其余 `0` | `0`（天然表示"没有方案"） |
| 最大价值 | 全部 `0` | 无（背包允许不选） |
| 是否可行 | `dp[0] = true`，其余 `false` | `false` |

注意第一行和第二行的区别：**求方案数时 `0` 恰好是正确的"没有方案"；求最小值时 `0` 是错误的"不需要任何代价"。**

## 遍历顺序

遍历顺序决定**算 `dp[i]` 时它依赖的值是否已经算好**。

| 问题类型 | 顺序 | 原因 |
|---|---|---|
| 一维线性 DP | `i` 从小到大 | `dp[i]` 依赖 `dp[i-1]`、`dp[i-2]` |
| 二维网格 | 外层行、内层列（或反过来） | 依赖上方和左方 |
| 0-1 背包 | 容量**从大到小** | 保证每个物品只用一次 |
| 完全背包 | 容量**从小到大** | 允许同一物品重复使用 |
| 区间 DP | 按**区间长度**从小到大 | `dp[i][j]` 依赖更短的区间 |

0-1 背包和完全背包只差遍历方向，这是 DP 最著名的"一行之差"：

<!-- #region template -->
```cpp
// 0-1 背包：容量倒序 → dp[j] 用的是"上一轮"的 dp[j - w]
for (int j = capacity; j >= weight; --j)
    dp[j] = max(dp[j], dp[j - weight] + value);

// 完全背包：容量正序 → dp[j] 用的是"本轮"已更新的 dp[j - w]
for (int j = weight; j <= capacity; ++j)
    dp[j] = max(dp[j], dp[j - weight] + value);
```
<!-- #endregion template -->

::: details 为什么倒序就能保证"只用一次"？

正序时，算 `dp[j]` 会用到 `dp[j-w]`，而 `dp[j-w]` 在本轮**已经被更新过**（可能已经包含了当前物品）。这就等于"同一个物品可以用多次"。

倒序时，`dp[j-w]` 还没被本轮修改，仍是上一轮的值，即"不含当前物品"的状态。所以每个物品只被考虑一次。

一维数组压缩本质上是把二维的 `dp[i][j]` 压成 `dp[j]`，倒序是为了模拟"还没被覆盖的上一行"。
:::

## 变体索引

### 变体 1：完全背包（[322](/topics/dp/322-coin-change)）

物品可重复选，容量正序。求最小值时要处理不可达状态。

### 变体 2：0-1 背包（416 分割等和子集）

每个物品一次，容量倒序。求"能否恰好装满"，用 `bool` 数组。

### 变体 3：线性 DP（70 爬楼梯、198 打家劫舍）

`dp[i]` 只依赖前一两项，可以滚动变量压缩空间。

```cpp
int prev = 1, curr = 1;               // 对应 dp[0], dp[1]
for (int i = 2; i <= n; ++i) {
    int next = prev + curr;           // 注意：先算再滚，顺序不能反
    prev = curr; curr = next;
}
```

### 变体 4：区间 DP（5 最长回文子串、516）

`dp[i][j]` 依赖 `dp[i+1][j-1]`，必须按长度递增遍历，否则依赖未算。

### 变体 5：状态压缩（状压 DP）

状态是一个集合时，用二进制位表示，`dp[mask][i]`。

## 坑点汇总

::: warning 坑点
1. **不可达状态用 0 表示**：求 `min` 时会把"不可达"当成"代价为 0"，结果偏小。
2. **`INF + 1` 溢出**：`INT_MAX + 1` 是 UB。用 `amount + 1` 这类"肯定超不过"的具体值，或转移前判 `!= INF`。
3. **背包遍历方向反了**：0-1 背包写成正序 → 物品被重复使用；完全背包写成倒序 → 只能用一个。
4. **滚动数组的更新顺序**：`next = prev + curr` 必须在 `prev = curr` **之前**，否则用错了值。
5. **答案位置错**：前缀型答案是 `dp[n]`，结尾型是 `max(dp[i])`。
6. **`dp` 数组大小差一**：`dp[n+1]` 才能放下下标 `0..n`，写成 `dp[n]` 访问 `dp[n]` 时越界。
:::

## 自检清单

写完一个 DP，按顺序问自己：

1. `dp[i]` 用一句**不带"和"字的自然语言**能说清吗？
2. 最后一步有几种可能？每一种对应转移方程里的哪一项？
3. `dp[0]` 的值是什么？它对应"什么都没选"的语义吗？
4. 不可达状态用的什么值？它在 `min`/`max` 里会不会被误用？
5. 遍历顺序下，`dp[i]` 依赖的每个值都已经算好了吗？

五个都答得出，代码基本就是对的。

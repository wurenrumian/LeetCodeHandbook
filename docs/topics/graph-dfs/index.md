# 图 DFS · 岛屿与判环

DFS 在数组上只要两个参数就够，到了图或网格上必须多问两句：**从哪儿出去？谁已经来过了？**

漏掉前一个是越界，漏掉后一个是死循环或者重复计数。这个专题的全部难点就在这两句：

> **越界检查决定"停在哪"，访问标记决定"不回头"。两个都到位，DFS 才会在有限步内结束。**

## 骨架里的三个位置

```cpp
void dfs(状态) {
    // ① 出口：越界 / 不是目标 / 已经访问过
    if (不能进) return;

    // ② 标记：进入这一格 / 这个点
    标记(状态);

    // ③ 展开：把"邻居"交给递归
    for (邻居 : 邻居集合) dfs(邻居);
}
```

三段分别对应三种改法：出口决定**判据**，标记决定**去重与判环**，展开决定**连通性怎么定义**。所有 DFS 变体都是在这三处动手，函数名和参数外壳几乎不变。

### 标记为什么不能放在递归之后

放在递归之后（写完再"撤销"）叫**回溯**，那是全排列、子集、八皇后那类题的做法 —— 它们的共同点是"一个元素在不同的方案里可以被重复选中"。

图不能这么干。图里有环，`dfs(A)` 可能绕一圈又回到 `A`。如果 `A` 的标记要到返回时才生效，这一圈就没有任何东西能拦住它 —— **无限递归，栈溢出**。

所以图 DFS 的标记是"**进入时就打，一次有效，不撤销**"。撤销的前提是"这条路走完了，别的路可能还要用它"，而图里不存在这个前提。

## 两个模板

网格 DFS 和邻接表 DFS 的差别只在第 ③ 步：邻居从哪来。

| | 网格 | 邻接表 |
|---|---|---|
| 节点身份 | `(row, col)` 两个下标 | 一个整数编号 |
| 邻居 | 四个方向的坐标偏移 | `graph[node]` 里存的列表 |
| 越界怎么处理 | 下标范围检查，**必须写** | 不需要，建表时已保证合法 |
| 标记放哪 | 原地改网格，或 `visited[row][col]` | `visited[node]` |
| 典型题 | [200 岛屿数量](/topics/graph-dfs/200-number-of-islands) | [207 课程表](/topics/graph-dfs/207-course-schedule) |

::: compare 网格：邻居是坐标偏移 | 邻接表：邻居是编号列表
```cpp
// 节点 = (row, col)
void dfs(vector<vector<char>>& grid,
         int row, int col) {
    if (row < 0 || row >= rows) return;
    if (col < 0 || col >= cols) return;
    if (grid[row][col] != '1') return;

    grid[row][col] = '0';   // 进入即标记
    for (const auto& dir : dirs)
        dfs(grid, row + dir[0],
                   col + dir[1]);
}
```
```cpp
// 节点 = 一个整数编号
void dfs(const vector<vector<int>>& graph,
         vector<int>& visited, int node) {
    visited[node] = 1;   // 进入即标记
    for (int next : graph[node]) {
        // 合法性由建表保证，
        // 这里不需要判越界
        if (visited[next]) continue;
        dfs(graph, visited, next);
    }
}
```
:::

### 网格为什么用 `dirs[4][2]`

四方向也可以写成四次递归调用，能跑。但方向本质上是**可数的数据**：上下左右是四个 `(Δrow, Δcol)` 对。

写成表的好处只有一个，但很值钱：**加方向只改数据，不改函数体。**

| 需求 | 改动 |
|---|---|
| 八联通（含对角线） | `dirs` 从 4 行扩到 8 行 |
| 只能往右、下走 | `dirs` 只留 `{1,0}`、`{0,1}` 两行 |
| 带权（每条边代价不同） | 表里加第三列存代价 |

四次手写递归时，加对角线要新增四行，且"当前走的是哪个方向"这个信息藏在调用顺序里 —— 想在递归里用方向做别的事（比如记录路径、按方向剪枝）就得再传一个参数。

::: warning 坑点
邻接表 DFS 里没有越界检查，**不代表没有越界风险**，风险被前移到了建表那一步 —— 建表时 `push_back` 的每一对 `(u, v)` 都必须是真实存在的节点编号。另外有向图和无向图的建表差别是**存一次还是两次**：207 存一次，存两次就把图变成无向的了，环会凭空变多（实测见 [207](/topics/graph-dfs/207-course-schedule) 的坑点 4）。
:::

## 标记时机：三种选择

| 做法 | 适用 | 代价 |
|---|---|---|
| 原地修改数据（`'1'` → `'0'`） | 网格，允许破坏输入 | 零额外空间 |
| `visited[row][col]` 布尔表 | 网格，不能改输入 | O(n × m) |
| `color[node]` 三色 | 有向图判环 | O(n)，但 `bool` 不够用 |

岛屿类问题选第一种。理由不只是"省一个数组"，而是**标记的语义和数据的语义恰好重合**：`'0'` 本来就表示水，而水按定义不属于任何岛。把 `'1'` 改成 `'0'`，一句话同时说了两件事 —— "我来过"和"这块地已经归入某个岛"。

::: info 补充
如果函数签名是 `const vector<vector<char>>&`，原地修改这条路直接关门，只能用 `visited`。面试时值得先问一句"可以原地改吗" —— 这句话同时也是在告诉面试官你想到了两种写法。
:::

## 有向图判环：bool 不够，要三种颜色

这是整个专题最容易被低估的一点。

`bool visited` 只能回答"**来过没有**"。判环要回答的是"**它是不是还压在当前这条路径上**"。在有向图里这两个问题不等价：

```
A → B → A
```

从 `A` 出发：`A` 标记已访问 → 走到 `B` → `B` 的邻居是 `A` → `visited[A]` 已经是 `true`。

此时该判定成环吗？**该**。可如果图是 `A → B`，`A → C → B` 这种菱形（`B` 被两次到达），`visited[B]` 也是 `true`，但**不该**判环 —— `B` 只是被两条不同路径到达，不是环。

两种情况的 `visited` 值完全一样，一个 `bool` 分不开。差别在于：前者 `A` 是 `B` 的**祖先**（还在递归栈上），后者 `B` 已经**走完并退出**了。于是把状态拆成三种：

| 颜色 | 含义 | 遇到它意味着 |
|---|---|---|
| `0` 未访问 | 还没进过 | 正常递归进去 |
| `1` 访问中 | **在递归栈上**，是当前路径的一个祖先 | 环在这里闭合，立刻返回 `false` |
| `2` 已完成 | 整棵子树走完且无环 | 这条路安全，直接跳过 |

状态 `2` 的意义是"**这条路径已经不经过它了**"。递归返回时写 `2`，等价于宣告它退出了栈。所以"遇到 `1`"精确地等价于"绕回了自己"，而"遇到 `2`"只是"走到了别人的成果"。

::: danger 易错
把 `color[node] = 2` 写在函数**开头**，三色立刻退化成两色：所有节点一进来就"已完成"，环永远检测不到，全图都返回 `true`。

**`1` 在进函数时写，`2` 在函数返回前写** —— 这两行的位置，就是判环算法的全部内容。
:::

## 什么时候该恢复现场

这是和回溯题最容易混淆的地方，判断标准只有一条：

> **标记的含义是"这个节点在当前路径上，不能用"→ 必须恢复；含义是"这个节点永远不用再访问了"→ 不能恢复。**

| 场景 | 标记语义 | 恢复吗 |
|---|---|---|
| 200 岛屿数量：`'1'` → `'0'` | 这块地归属已确定 | 不恢复 |
| 207 判环：`1` → `2` | 这棵子树已验证完 | 不恢复（`2` 是保留结论） |
| 全排列 / 子集：`used[i]` | 这个位置本轮被占了 | **恢复** |
| 找所有路径（如 797） | 当前路径上的节点 | **恢复**（`path.pop_back()`） |

按"结果是不是一棵生成树/一个连通分量"来记更省事：**DFS 求连通性时结果是一次性的**（淹掉的岛不会浮回来），**DFS 求所有方案时结果要被反复复用**（同一个数可以出现在不同排列里）。

## 变体索引

### 变体 1：连通块计数（[200 岛屿数量](/topics/graph-dfs/200-number-of-islands)）

外层扫一遍网格，每遇到一个未标记的目标格就 `++count` 并把整片淹掉。计数发生在 DFS **之前** —— 因为能进 DFS 的格子，必然是一片新区域的第一格。

### 变体 2：有向图判环（[207 课程表](/topics/graph-dfs/207-course-schedule)）

三色 DFS，外层对每个未访问点起一次 DFS（图可能不连通）。同一个 `dfs` 换成"每次到达就撤销"就是求所有拓扑序，换成"记录出栈顺序"就是拓扑排序。

### 变体 3：最大连通块

200 的 `dfs` 改成返回"淹掉多少格"，外面取 `max`：

```cpp
int dfs(vector<vector<int>>& grid, int row, int col) {
    if (row < 0 || row >= rows) return 0;
    if (col < 0 || col >= cols) return 0;
    if (grid[row][col] == 0) return 0;
    grid[row][col] = 0;
    int area = 1;                       // 自己算一格
    for (const auto& dir : dirs)
        area += dfs(grid, row + dir[0],
                          col + dir[1]);
    return area;
}
```

对应 695 岛屿的最大面积。**返回值是"这一片有多大"，副作用是"这一片被淹了"** —— 两个信息同时用，`void` 就不够了。

### 变体 4：从边界出发

1254 统计封闭岛屿：先在四条边界上把所有陆地淹掉（它们一定不是封闭的），剩下的每片岛屿都被水包住，答案就是剩下的连通块数。

```cpp
for (int row = 0; row < rows; ++row) {
    dfs(grid, row, 0);
    dfs(grid, row, cols - 1);
}
```

**思路的转变比代码重要**：不是"判断每片岛屿封不封闭"，而是"先把能确定不封闭的全部排除"。

## 坑点汇总

::: warning 坑点
1. **先取值再判越界**：`if (grid[row][col] != '1') return;` 写在范围检查前面，`row == -1` 时直接读越界内存。**范围检查必须是函数体第一句**。

2. **忘了标记**：`grid[row][col] = '0'` 漏写，两个相邻格互相递归，无限次进出 —— 表现是段错误，不是死循环（递归版死循环的报法是爆栈）。

3. **标记写在递归之后**：同样爆栈，而且现象和上一条一样，很难区分。**标记必须在 `for` 展开之前**。

4. **`dfs` 参数按值传网格**：`void dfs(vector<vector<char>> grid, ...)` 每层递归拷贝一份 n×m 的网格，标记也丢了 → 内存和栈双爆。参数一律 `&`。

5. **有向图用 `bool visited` 判环**：`A → B → A` 返回"无环"。这是**静默**错误，测试用例少了根本发现不了。

6. **忘了外层循环**：207 只从 0 号点起 DFS，环藏在别的连通分量里就漏了。图不连通是常态，`for` 遍历每个未访问点是必须的。
:::

::: danger 易错
递归深度。DFS 的空间开销就是递归栈深度，最坏情况等于**一条路径上的节点数**：

- 200 题网格 300 × 300，一条蛇形走廊能让路径绕过整格 → 8.9 万层
- 207 题 `numCourses <= 2000` → 一条链 2000 层

**栈有多大取决于平台，这一点常被忽略**：

| 平台 | 默认栈 | 实测临界深度（`-O0`） |
|---|---|---|
| Linux（含力扣判题环境） | 8 MB | 约 13 万层 |
| **Windows** | **1 MB** | **约 1 万层** |

所以"200 题能过"只在 OJ 上成立。**在本机 Windows 实测：100 × 100 通过，150 × 150 直接 `Segmentation fault`（栈溢出）**——而力扣约束允许 300 × 300。也就是说，合法的测试数据在 Windows 本地就会崩，容易让人误以为自己写错了。

真遇到大网格，把 DFS 换成 BFS（队列代替递归栈），或者用显式栈。这一点在 [200 岛屿数量](/topics/graph-dfs/200-number-of-islands) 那页有对照代码。
:::

## 自检清单

写完一段 DFS，用这五个问题过一遍：

- 范围检查是不是函数体第一句？（在取下标之前）
- 标记在哪一行？在 `for` 展开之前吗？
- 这个标记该不该恢复？它是"当前路径占用"还是"永久归属"？
- 图连通吗？需不需要外层对每个点起一次 DFS？
- 最坏递归深度是多少？超过十万级就该考虑 BFS 或显式栈。

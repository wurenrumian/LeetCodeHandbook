# 回溯 · 决策树的 DFS

回溯不是一种新算法，它是**把"枚举所有可能"这件事组织成一棵树**：

> 把每个"还没做的决定"排成一层，从根出发走一条路径，走到不能再走就**退回上一步**换下一个选项。

DFS 负责"往下走"，**撤销**负责"退回来"。两者缺一，代码就不是回溯。

## 三段式：做选择 → 递归 → 撤销

所有回溯题的骨架都是这三行，一个字都不用改：

```cpp
for (每个候选 c : 当前层的选择) {
    // 1. 做选择：把 c 记进 path
    // 2. 递归：带着新 path 往下走一层
    // 3. 撤销选择：把 c 从 path 里拿掉
}
```

第 3 步是**唯一一件"看起来多余"的事** —— 递归都返回了，为什么还要擦掉？下一节说清这件事。

## 为什么必须撤销

因为 `path` 是**整个搜索过程共享的一个数组**。它不是"每个分支各有一份"，而是所有分支轮流借用同一块内存。

```
          根  path=[]
        /              \
    选 1                选 2
      |                  |
   path=[1]           path=[1,2]   ← 没撤销，2 接在 1 后面
      |
   选 3
      |
 path=[1,3]                        ← 实际变成 [1,2,3]
```

正确的轨迹是：

- 走 `选 1` 分支一路到底，`path` 长到 `[1,2,3]`
- 逐层返回时**逐层擦掉**：先 `[1,2]`，再 `[1]`，最后 `[]`
- 到根时 `path` 已空，`选 2` 分支从 `[2]` 开始

不撤销就是把这个"逐层擦掉"省了，所以 `选 2` 分支拿到的是 `[1,2,3]` 而不是 `[]`。

**撤销就是"把这一层对共享状态的修改还原"**，让兄弟分支拿到干净的起点。这和不撤销 `used[i]` 是同一个道理，两者必须成对。

::: danger 易错
不撤销**不一定崩溃，甚至不一定少结果** —— 它经常只是让结果内容错掉。78 题里忘了 `path.pop_back()` 仍然返回 8 个结果，只是每个都比正确值长。这种"数量对、内容错"的最难查，所以写完一定对照具体用例看内容，别只看 `result.size()`。
:::

## 三种问题，一张表分清

排错回溯题的 90% 就是把这三类混了。判据只有一个：**顺序算不算不同**。

| 问题 | 例 | 顺序有意义？ | 去重手段 | 收集时机 |
|---|---|---|---|---|
| 排列 | [46](/topics/backtracking/46-permutations) | 有，`[1,2]≠[2,1]` | `used[i]`，每层**从 0 扫** | 叶子 |
| 组合 / 子集 | [78](/topics/backtracking/78-subsets) | 无 | `start`，递归传 `i + 1` | **每个节点** |
| 含重复的排列 | 47 | 有 | 排序 + `used[i-1]` 同层跳过 | 叶子 |
| 含重复的子集 | 90 | 无 | 排序 + `nums[i-1]` 同层跳过 | 每个节点 |

记住这张表的两个规律，就不会写错：

- **`used` 管"顺序有意义"，`start` 管"顺序无意义"**
- **收集在叶子 = 要求用完全部元素（排列），收集在节点 = 允许中途停下（子集）**

再加一条：**有重复元素就一定要先 `sort`**，因为同层去重靠的是"相等元素相邻"。

## 通用骨架：两版只差一个参数

::: compare 排列型：used + 每层从 0 扫 | 子集型：start + 每层从 start 扫
```cpp
// 顺序有意义：[1,2] 和 [2,1] 都要
void backtrack() {
    if (path.size() == n) {
        result.push_back(path);   // 叶子才收
        return;
    }
    for (int i = 0; i < n; ++i) {
        if (used[i]) continue;
        used[i] = true;           // 做选择
        path.push_back(nums[i]);
        backtrack();              // 仍从 0 扫
        path.pop_back();          // 撤销
        used[i] = false;
    }
}
```
```cpp
// 顺序无意义：选过的下标只往后走
void backtrack(int start) {
    result.push_back(path);       // 每个节点都收
    for (int i = start; i < n; ++i) {
        path.push_back(nums[i]);
        backtrack(i + 1);         // 关键：i + 1
        path.pop_back();          // 撤销
    }
}
```
:::

左栏的 `if (used[i]) continue` 保证"同一个下标只用一次"；右栏的 `i + 1` 保证"下标只增不减"。两者都在做同一件事 —— **不生成重复的路径**，只是对"什么算重复"的定义不同。

## 两处剪枝，位置不能混

| 位置 | 写法 | 解决什么 | 例子 |
|---|---|---|---|
| 循环内 `continue` | 进 `path` 之前跳过 | **同层去重**：兄弟分支别试同一个值 | 47 / 90 的 `nums[i] == nums[i-1]` |
| 递归前判断 | `if (...) return;` 或 `break` | **整枝砍掉**：这条路走下去不可能有解 | 39 组合总和的和超限、括号生成的左右计数 |

::: warning 坑点
**同层去重和全局去重是两件事。** `if (i > 0 && nums[i] == nums[i-1]) continue;` 是**全局**去重，它会把合法分支也砍掉 —— 90 题 `[1,2,2]` 用它只能得到 4 个子集，正确是 6 个。同层去重必须写成 `i > start`。
:::

"同层"的意思是：在**同一个 `start` 值的这一轮 `for`** 里，前一个相等元素已经被选过了。而 `used[i-1] == false` 表达的是"`nums[i-1]` 不在当前路径上"，也就等价于"它在这一层已经被回撤掉了"。

## 变体索引

### 变体 1：全排列（[46](/topics/backtracking/46-permutations)）

顺序有意义，`used` 标记"在当前路径上用过"，每层从 0 重新扫。

### 变体 2：子集（[78](/topics/backtracking/78-subsets)）

顺序无意义，`start` 保证下标递增，递归开头就收集。

### 变体 3：含重复元素（47 / 90）

先 `sort`，再在**同一层**跳过相等元素。排序是前提 —— 不排序，相等的元素不相邻，就无从判断"是否已试过"。

### 变体 4：组合总和（39 / 40）

在子集骨架上加"和"的剪枝：`sum > target` 直接返回；元素可重复用时递归传 `i` 而不是 `i + 1`。

### 变体 5：棋盘类（51 N 皇后 / 37 解数独）

一层对应棋盘的一行，候选是"这一行的哪个列"。去重不靠 `used` 数组，而靠**三组列/对角线标记**。

## 坑点汇总

::: warning 坑点
1. **忘记撤销**：`path` 污染兄弟分支，结果变长或错乱。`path.push_back` 和 `path.pop_back` 必须成对出现。注意它**不一定改结果数量** —— 78 题漏了 `pop_back` 仍然返回 8 个结果，只是内容全错。

2. **`result.push_back(path)` 存了引用**：写成 `vector<vector<int>*>` 时所有结果指向同一个 `path`，最后全是空数组；写成 `vector<reference_wrapper<vector<int>>>` 也是同样的坑。**存值**（`vector<vector<int>>`）就没事 —— `push_back` 会自动拷贝一份。

3. **`result` 按值传参**：`void dfs(vector<vector<int>> result)` 每次递归复制一份，改的是副本，回到 `main` 里 result 还是空的。

4. **78 把收集写在循环后面**：子集要求"每个节点都是答案"，写在循环后虽然仍是 8 个、内容也对，但**顺序反了**（`{123}{12}…{}`），整数组比较的断言会炸；而真的只在叶子收（`if (start == n)`）则只剩 4 个。两种写法都要分清。

5. **47 / 90 用了全局去重**：判 `i > 0` 而不是 `i > start`，会砍掉合法分支。见上一节。

6. **47 忘了 `!used[i-1]`**：`[1,1,2]` 会得到 0 个结果，因为第一个 `1` 一进来就把第二个 `1` 屏蔽了。

7. **78 递归传 `start + 1`**：`i` 和 `start` 不是一回事。传 `start + 1` 时 `[1,2,3]` 会得到 16 个结果，正确是 8 个。
:::

## 自检清单

写完一段回溯，先别提交，按顺序问：

1. `path.pop_back()` 和 `used[i] = false` 是不是**每个** `push` 都有对应的还原？
2. 收集语句在**函数开头**（子集）还是 **`return` 之前**（排列）？和题目要求一致吗？
3. 循环的起点是 `0` 还是 `start`？和"顺序有没有意义"对得上吗？
4. 递归传的是 `i + 1`、`i` 还是 `0`？三者分别对应子集、可重复组合、排列。
5. 有重复元素吗？有就先 `sort`，再确认去重条件用的是 `i > start`（或 `!used[i-1]`）。
6. 空输入（`n == 0`）会不会崩？力扣通常保证 `n >= 1`，但本地 `assert` 值得加一条。

::: info 补充
回溯的复杂度不能只看"树有几个节点"。排列是 O(n!)，子集是 O(2ⁿ)，但**每条路径的复制**是 O(n)，所以排列的总复杂度是 O(n · n!)，子集是 O(n · 2ⁿ)。指数级算法只在小 `n`（通常 ≤ 8~10）时可用，这是题目给约束的原因。
:::

::: tip 提示
回溯和 [DFS](/topics/graph-bfs/) 是同一套遍历，区别只在**要处理的那份状态是不是"路径"**。BFS 遍历图时状态是"走到了哪个节点"，回溯遍历决策树时状态是"这条路径上做了哪些选择"。所以回溯多了一步"撤销"—— 因为路径是可变的，而图上的节点不是。
:::

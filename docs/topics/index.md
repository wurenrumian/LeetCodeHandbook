# 专题总览

五个专题，每个都是一份"可背诵模板 + 变体清单"。顺序建议按下面从易到难，每个专题读完后立刻去 [题目索引](/problems/) 挑同标签的题刷。

| 专题 | 一句话核心 | 典型信号 | 题数 |
|---|---|---|---|
| [二分查找](/topics/binary-search/) | 每次砍掉一半**确定的**不可能区间 | 有序 / 可判定单调 / 求边界 | 2 |
| [滑动窗口](/topics/sliding-window/) | 右端扩张，左端在破坏条件时收缩 | 求"最长/最短的连续子段" | 1 |
| [双指针](/topics/two-pointers/) | 两个下标各自单调移动，互不回头 | 有序数组 / 原地修改 / 去重 | 1 |
| [动态规划](/topics/dp/) | 用状态把"重复子问题"的答案存下来 | 求方案数 / 最优值 / 可不可行 | 1 |
| [树的遍历 · BFS](/topics/graph-bfs/) | 队列 + **层界快照**，一层一层处理 | 按层 / 最短步数 / 无权最短路 | 1 |

## 怎么选专题

拿到一道题，先别想"用什么算法"，先看这三个问题：

1. **数据有序吗？或者答案有单调性吗？**
   有序 + 求某个位置 → 二分。答案空间有单调性（"能"之后一定一直"能"）→ 二分答案。

2. **要找的东西是"连续的"吗？**
   子串、子数组、连续区间 → 滑动窗口。窗口的两个端点都只往右走，这是它能做到 O(n) 的唯一原因。

3. **是"从已有状态推下一个状态"吗？**
   能用前面的结论算出后面的 → DP。关键不是"看起来复杂"，而是**子问题会不会被重复求解**。

4. **问"最少几步""按层"？**
   边权全为 1 → BFS。有权重就用 Dijkstra，那是另一个专题。

## 每个专题页有什么

- **统一模板**：能背下来的骨架，注释标出"这里可以改"
- **变体清单**：同一模板在不同条件下的改法，附带"改哪一行"
- **适用信号**：题目描述里出现什么词时该想到它
- **坑点汇总**：不是零散记录，而是按"改错会怎样"分类

## 一个提醒

模板的价值在于**减少你要现场决策的次数**，不在于背下字符。真正需要判断的永远只有两三处：

- 区间是左闭右闭还是左闭右开？
- 循环条件是 `<` 还是 `<=`？
- 收缩边界时是 `= mid` 还是 `= mid + 1`？

把这三处想清楚，其余都是机械翻译。每道题的"模板对照"就是在练这三处。

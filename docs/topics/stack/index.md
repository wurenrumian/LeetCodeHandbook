# 栈与单调栈 · 模板与变体

栈只有一个性质：**后进先出（LIFO）**。这条性质单独看毫无意思，但它恰好对应一类问题的形状 ——

> **"最近的、还没配对的"东西。**

括号匹配要找"左边最近的那个还没配对的左括号"；下一个更大元素要找"左边最近的、还没找到答案的那个元素"。两者问的都是"最近 + 未结算"，所以在数据结构上都被栈收容。

栈题目真正的分歧不在栈，而在**你什么时候弹栈**。按这一点切开，只有两类。

## 两类问题，一个判据

| | 配对型 | 单调栈 |
|---|---|---|
| 代表题 | [20 有效的括号](/topics/stack/20-valid-parentheses) | [739 每日温度](/topics/stack/739-daily-temperatures) |
| 栈里存什么 | 等配对的**开符号**（或下标） | **下标**，且下标对应的值单调 |
| 什么时候弹 | 遇到**终止符**（右括号） | 新元素**破坏了单调性** |
| 弹出时做什么 | 检查类型是否匹配，不匹配就失败 | **结算答案**（栈顶元素等到结果了） |
| 结束状态 | 栈必须**为空** | 栈里剩下的元素，答案有默认值 |
| 一句话 | 遇到右括号，弹栈顶看是否匹配 | 栈内单调，弹出时结算答案 |

判据可以压成一句：

> **弹栈是"失败"还是"结算"？**
>
> 弹出后要求"必须匹配否则报错" → 配对型。弹出后直接写答案 → 单调栈。

## 配对型：遇终止符弹栈顶

核心不变式只有一句：**栈里的东西，全是"已经读入、还没有被配对"的开符号。**

于是遇到一个闭符号时，能配它的只可能是"最近的那个未配对的"—— 也就是栈顶。不需要在栈里搜，不需要记住全部历史。

```cpp
for (char ch : s) {
    if (isOpen(ch)) {
        stack.push_back(ch);
        continue;
    }
    // 闭符号：先判空，再比栈顶
    if (stack.empty()) return false;
    if (stack.back() != want(ch)) return false;
    stack.pop_back();
}
return stack.empty();      // 扫完必须空
```

三个位置都可能失败，各自对应一种错误：**栈空时遇到闭符号**（闭的多了）、**栈顶不匹配**（类型错或交叉嵌套）、**扫完栈非空**（开的多了）。三个都堵住，才是充要条件。

## 单调栈：入栈时结算被挤出去的元素

单调栈的模板和配对型长得很像，但语义完全不同：

```cpp
for (int i = 0; i < n; ++i) {
    // 新元素破坏单调性 -> 栈顶等到了答案
    while (!stack.empty() && breaks(stack.back(), i)) {
        int past = stack.back();
        stack.pop_back();
        answer[past] = ...;
    }
    stack.push_back(i);    // 自己入栈，等它的答案
}
```

### 核心洞察：一次入栈，同时结算一批

这是单调栈能 O(n) 的全部原因，值得单独说清。

新元素 `nums[i]` 入栈前，会先把栈顶那些"不如它"的元素弹掉。**这些被弹出的元素，它们的答案都是 `i`。** 不是"其中一个"，是**同时**。

它们凭什么同时有答案？因为栈内是**单调**的，所以"还没结算"的元素按大小排好了序，而且是**连续的一段**。以递减栈（栈底最大、栈顶最小）为例：

- 栈顶是这一段里最小的，所以最容易满足"比它大"这个条件 —— 新元素一来就先满足它
- 弹掉栈顶后，新的栈顶比刚才那个**更大**一点；如果新元素比它还大，它就也能结算
- 就这样一路往上，直到撞上一个真正比新元素大的才停

所以被结算的一定是**从栈顶往下连续的一段**，不存在"跳过中间某个"的情况。这就是 `while` 能连着弹的理由：每次弹出的条件都是同一个 `nums[i] > nums[stack.back()]`，弹一次检查一次，直到不满足为止。

这就引出本专题最值钱的一句话：

> **每个元素入栈一次、出栈一次，总共 2n 次操作 —— 和它被弹掉时结算了几个元素无关。**

内层 `while` 看起来像嵌套循环，但它的总执行次数被"每个下标最多弹出一次"卡死。所以外层 `n` 次 + 内层累计 `n` 次 = **O(n)**。这是均摊分析里最干净的一个例子，面试里问到复杂度必须能这么解释。

### 两个决定，决定一切

写单调栈时真正要做的决策只有两个：

**决定一：栈里存值还是存下标？**

判据：**答案里有没有"距离 / 位置 / 长度 / 个数"。**

| 答案要什么 | 存什么 | 例子 |
|---|---|---|
| 就是那个元素的值 | 值或下标都行 | 496 下一个更大元素 I |
| 隔多远 / 第几天 | **必须存下标** | [739](/topics/stack/739-daily-temperatures) |
| 能接多少水 / 多大矩形 | **必须存下标** | 42、84 |

存下标永远不亏：值可以用 `nums[idx]` 取，位置就是 `idx` 本身。存值则直接丢掉了位置，而位置往往才是答案。

**决定二：栈是递增还是递减？**

判据：**栈的单调方向 = 结算条件的反向。**

| 找什么 | 栈方向 | 弹栈条件 |
|---|---|---|
| 右边第一个**更大**的 | 递减（栈顶最小） | `nums[i] > nums[stack.back()]` |
| 右边第一个**更小**的 | 递增（栈顶最大） | `nums[i] < nums[stack.back()]` |

理由很简单：栈顶必须是"最容易被新元素满足"的那个。找更大的话，栈顶该是最小值，新元素一来就可能满足它；如果栈顶是最大值，`while` 一次都进不去，算法空转。

## 完整模板对照

::: compare 配对型：比栈顶 | 单调栈：结算栈顶
```cpp
// 栈内存"未配对的开符号"
for (char ch : s) {
    if (isOpen(ch)) {
        stack.push_back(ch);
        continue;
    }
    if (stack.empty())
        return false;
    if (stack.back() != want(ch))
        return false;
    stack.pop_back();
}
return stack.empty();
```
```cpp
// 栈内存下标，值单调递减
for (int i = 0; i < n; ++i) {
    while (!stack.empty()
           && nums[i] > nums[stack.back()]) {
        int past = stack.back();
        stack.pop_back();
        answer[past] = i - past;
    }
    stack.push_back(i);
}
// 剩下的 answer 保持默认值
```
:::

两栏的骨架几乎一样：**一个 `for` 扫过去，一个"看栈顶"的动作，一个 `push_back`。** 差别只在"看栈顶"之后干什么 —— 左边是判定后 `return false`，右边是写 `answer` 后继续弹。

## 坑点汇总

::: warning 坑点
1. **栈空时弹栈**：`stack.back()` 和 `stack.pop_back()` 在空容器上是**未定义行为**（`vector` 表现为读垃圾值或 `size() - 1` 回绕成巨大下标）。`!stack.empty()` 必须写在 `&&` 的**左边**，靠短路求值保护。依赖哨兵保证栈永不为空时（如 84 题首尾补 `0`），要把这个前提写进注释。

2. **遍历结束后栈里还有元素没结算**：单调栈里这些元素的答案是什么，**每题不同**。739 是 `0`（初始化为 0 就够）；"下一个更大元素的值"是 `-1`（初始值不能是 0）；42/84 则要靠**哨兵**强制弹空。不先想清楚这一点，初始值一定会错。

3. **单调栈存了值而不是下标**：栈里一旦存值，`today - past` 里就没有"past 是哪一天"的信息，算不出距离。而且把温度值当下标去访问 `temperatures[73]` 会**越界**（数组长度可能只有 10）。

4. **相等元素该不该弹**：`[50, 50, 50]` 在"下一个更高温度"里答案是 `[0, 0, 0]`，用 `>=` 会得到 `[1, 1, 0]`。判据是题目措辞 —— "更高"是严格大于，"不低于"才是 `>=`。503（循环数组）在全等输入上对这个选择尤其敏感。
:::

::: danger 易错
**把配对型"扫完必须栈空"的结论套到单调栈上。** 配对型里 `return stack.empty()` 是正确性的一半，单调栈里栈非空却是**正常且必然**的 —— 递减输入 `[90, 80, 70, 60]` 会让栈涨到 `n` 个元素且一个都不弹。

反过来也一样：单调栈的"弹出即结算"套到括号匹配上，`([)]` 会被误判为合法（因为它只检查"栈里有没有 `(`"，而不检查栈顶）。

两类的差别不在代码形状，在**你相信哪个不变量**。
:::

## 后续练习的推荐顺序

1. **496 下一个更大元素 I** —— 739 的简化版，答案就是值本身，先确认骨架记牢了
2. **503 下一个更大元素 II** —— 循环数组，遍历 `2n` 次取模，练"相等弹不弹"
3. **42 接雨水** —— 单调栈第一次需要"弹出后再读新栈顶"来算宽度
4. **84 柱状图中最大的矩形** —— 哨兵技巧的典型战场，也是单调栈里最难调的一题
5. **150 逆波兰表达式 / 155 最小栈** —— 换回"栈是求值工具"，不涉及单调性

## 自检清单

写完任何一道栈题，用这三个问题过一遍：

- **栈里存的是什么？** 值还是下标 —— 说得出理由吗？
- **弹栈的条件是什么？** 用 `>` 还是 `>=` —— 和题目措辞对得上吗？
- **循环结束后栈里的元素？** 答案该是什么 —— 是误判成"必须为空"，还是漏了初始化？

# 739 · 每日温度

<ProblemMeta id="739" difficulty="中等" title="每日温度" :tags="['单调栈', '存下标', '递减栈']" url="https://leetcode.cn/problems/daily-temperatures/" />

::: params 栈与单调栈
| 要素 | 本题取值 |
| --- | --- |
| 栈里存什么 | `vector<int> stack` 存**下标**不存温度，值靠 `temperatures[idx]` 取 |
| 入栈前做什么 | 先 `while (temperatures[today] > temperatures[stack.back()])` 把挡路的栈顶弹空 |
| 出栈时机 | 每弹出一个 `past` 就当场结算 `answer[past] = today - past`，剩下的保持 `0` |
:::

::: cheat 速查卡
- **什么时候用**：对每个元素求"**右边第一个比它大**（或小）的元素"离它多远
- **核心不变式**：栈内下标对应的温度**单调递减**，栈里全是"还在等答案"的元素
- **一句话模板**：新元素比栈顶大就弹栈结算，弹到不满足为止，再把自己压进去
- **复杂度**：时间 **O(n)**（每个下标进出栈各一次）、空间 **O(n)**
:::

## 题意重述

给一个温度数组，对每一天求出**还要等多少天**才会出现更高的温度。之后都不会更高则填 `0`。

```
输入: temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
输出:                   [ 1,  1,  4,  2,  1,  1,  0,  0]

输入: temperatures = [30, 40, 50, 60]
输出:                   [ 1,  1,  1,  0]

输入: temperatures = [90, 80, 70, 60]
输出:                   [ 0,  0,  0,  0]
```

三个例子的重点：

1. 第一个是主用例，注意下标 2（`75`）等 4 天到 `76`，而中间的 `71`、`69`、`72` 都比它低，**都不是答案**
2. 第二个严格递增：每个都只等 1 天，最后一天永远等不到
3. 第三个严格递减：**全部是 0**，这是"遍历结束后栈里还有元素"的极端情形

## 从朴素到最优

朴素做法是对每一天往后线性扫，遇到更高的就停。严格递减的输入下，第 `i` 天要扫到末尾，总代价 O(n²)。10⁵ 的数据量会超时。

要优化，先问一个关键问题：**扫到 `71` 的时候，前面那些还没找到答案的日子，还需不需要一个个记住？**

看主用例的下标 0..4：

```
温度:  73  74  75  71  69  72
下标:   0   1   2   3   4   5
```

- 读到下标 5（`72`）时，`69`（下标 4）的答案确定是 1 天
- 接着 `71`（下标 3）的答案也确定是 2 天
- 但 `75`（下标 2）**不能**结算 —— `72 < 75`

注意被结算的两个是**从后往前连续**被结算的：`69` 先，然后 `71`。为什么？因为还没结算的那些，温度是从前到后**递减**的（`75 > 71 > 69`）。既然递减，从末尾（最小的）开始往上比，第一个比 `72` 小的先被淘汰，接着下一个……

> **"还没结算的元素，温度从栈底到栈顶单调递减" —— 保证了这个结构恰好是个栈。**

这句话就是整个单调栈的立足点。它意味着：新元素只可能结算栈顶那一小段，而不会被它已经越过的更小值挡住。每个下标最多被压一次、弹一次，总代价 O(n)。

## 模板对照

::: compare 单调栈通用骨架（递减栈） | 739 本题：结算距离
```cpp
// 求"右边第一个更大的元素"的下标
vector<int> stack;   // 存下标，不存值

for (int i = 0; i < n; ++i) {
    // 新元素更大 -> 栈顶等到了答案
    while (!stack.empty()
           && nums[i] > nums[stack.back()]) {
        int past = stack.back();
        stack.pop_back();
        answer[past] = i;     // 骨架里记下标
    }
    stack.push_back(i);
}
```
```cpp
// 本题：答案是"相差几天"，不是下标
vector<int> stack;

for (int today = 0; today < n; ++today) {
    while (!stack.empty()
           && temperatures[today]
              > temperatures[stack.back()]) {
        int past = stack.back();
        stack.pop_back();
        // 下标相减 = 天数差
        answer[past] = today - past;
    }
    stack.push_back(today);
}
// 栈里剩下的，answer 保持 0
```
:::

两栏的骨架**完全相同**，只改了最后那行赋值的右侧：通用骨架写 `answer[past] = i`（"答案在哪"），本题写 `answer[past] = today - past`（"隔多远"）。

这个差别看着微不足道，但它决定了数据结构的选择 —— 见下面「为什么栈里必须存下标」。

### 为什么栈里存下标，不存温度值

假如栈里存的是温度值 `73, 71, 69`：

- `72` 进来时，你知道 `69` 等到答案了
- 但**你不知道这个 `69` 是哪一天的**，所以算不出 `today - past`

存值的话，唯一能给出的答案是"温度值是多少" —— 而题目问的是**距离**。为了补上位置信息，你就得额外维护一个 `map<温度, 下标>`，可温度会重复（`[50, 50, 50]`），这个映射根本不唯一。

**存下标就同时拥有了值和位置**：值用 `temperatures[idx]` 取，位置就是 `idx` 本身。多花一个 `vector<int>` 的代价，把两类信息一次性拿全。

::: tip 提示
这条规则可以推广到整个栈专题：

> 只要答案涉及**距离、位置、长度、个数**，栈里就存下标；只有答案就是"值本身"时，才可以直接存值。

[20 有效的括号](/topics/stack/20-valid-parentheses) 里存的是字符，因为那题只问"合不合法"；32 最长有效括号里就得存下标，因为要算长度。同一专题，两种选择，判据就是上面这一句。
:::

### 为什么是递减栈

栈内单调递减 = 栈顶是**最小值**。这个方向不是随手定的，它由"结算条件"反推出来：

| 想要什么 | 栈的单调方向 | 弹栈条件 |
|---|---|---|
| 右边第一个**更大**的（本题） | 递减，栈顶最小 | `temperatures[today] > temperatures[stack.back()]` |
| 右边第一个**更小**的 | 递增，栈顶最大 | `temperatures[today] < temperatures[stack.back()]` |

因为要找更大的，所以只有当新元素比栈顶**大**时栈顶才有答案。而如果栈里是递减的，新元素一旦大于栈顶，就可能连续大于好几个 —— 它们全都能被结算，`while` 一路弹过去。如果栈不是递减的（比如递增），栈顶是最大值，新元素几乎永远比它小，`while` 一次都不进，算法直接失效。

**一句话记法：栈的单调方向 = 结算条件的反向。** 找更大 → 递减栈；找更小 → 递增栈。

## 完整可编译代码

```cpp
#include <cassert>
#include <iostream>
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> dailyTemperatures(const vector<int>& temperatures) {
        int n = static_cast<int>(temperatures.size());
        vector<int> answer(n, 0);

        // 栈里存的是下标，不是温度值
        vector<int> stack;
        stack.reserve(n);

        for (int today = 0; today < n; ++today) {
            // 今天比栈顶那天热，栈顶那天的答案就是今天
            while (!stack.empty()
                   && temperatures[today] > temperatures[stack.back()]) {
                int past = stack.back();
                stack.pop_back();
                answer[past] = today - past;   // 下标相减才是天数差
            }
            stack.push_back(today);
        }

        // 栈里剩下的都是"后面没有更高温度"的，answer 保持 0
        return answer;
    }
};

int main() {
    Solution sol;

    {
        vector<int> t{73, 74, 75, 71, 69, 72, 76, 73};
        vector<int> want{1, 1, 4, 2, 1, 1, 0, 0};
        assert(sol.dailyTemperatures(t) == want);
    }
    {
        vector<int> t{30, 40, 50, 60};
        vector<int> want{1, 1, 1, 0};           // 严格递增
        assert(sol.dailyTemperatures(t) == want);
    }
    {
        vector<int> t{30, 60, 90};
        vector<int> want{1, 1, 0};
        assert(sol.dailyTemperatures(t) == want);
    }
    {
        vector<int> t{90, 80, 70, 60};
        vector<int> want{0, 0, 0, 0};           // 严格递减
        assert(sol.dailyTemperatures(t) == want);
    }
    {
        vector<int> t{50};
        vector<int> want{0};                    // 单元素
        assert(sol.dailyTemperatures(t) == want);
    }
    {
        vector<int> t{};
        vector<int> want{};                     // 空输入
        assert(sol.dailyTemperatures(t) == want);
    }
    {
        vector<int> t{50, 50, 50};
        vector<int> want{0, 0, 0};              // 相等不弹出
        assert(sol.dailyTemperatures(t) == want);
    }
    {
        vector<int> t{55, 38, 53, 81, 61, 93, 97, 82, 43, 33};
        vector<int> want{3, 1, 1, 2, 1, 1, 0, 0, 0, 0};
        assert(sol.dailyTemperatures(t) == want);
    }

    cout << "all tests passed" << endl;
    return 0;
}
```

`main` 里 8 个用例按输入形状分类，覆盖了单调栈的每种退化情形：严格递增（栈里最多 1 个元素）、严格递减（栈涨到 `n` 且从不弹出）、全部相等（弹出条件永不成立）、单元素、空输入，以及一个随机形状的力扣官方用例。

## 逐段拆解

::: semantics
| 字段 | 含义 | 在代码里怎么用 |
| --- | --- | --- |
| `answer[i]` | 第 `i` 天要等的天数；**等不到就是 0** | 构造时全部填 0，之后只在被弹出时写入一个正数 |
| `stack` | 存**下标**，对应温度从栈底到栈顶**单调递减** | 只存"还没等到答案"的日子 |
| `today` | 今天的下标 | 外层循环变量，同时充当"当前候选答案" |
| `temperatures[today]` | 今天的温度 | 和 `temperatures[stack.back()]` 比较，比的是值 |
| `stack.back()` | 栈顶下标 —— 温度最低的、最"容易满足"的那天 | 它是最可能被 `today` 结算的，所以只检查它 |
| `while` 而非 `if` | 今天可能同时是多个日子的答案 | 弹掉一个后栈顶变了，要继续比 |
| `past` | 被结算的那天的下标 | `pop_back` **之前**取，弹出后就拿不到了 |
| `today - past` | 天数差 | 两个下标都在 `[0, n)`，差值不会为负 |
:::

### 为什么 `pop_back` 之前必须先取出 `past`

```cpp
int past = stack.back();
stack.pop_back();
answer[past] = today - past;
```

这三行的顺序不能动。`pop_back()` 之后 `stack.back()` 就变成了**下一个**元素，此时再读就结算错了对象。这种错误极其隐蔽：数组不越界、程序不崩溃，只是答案错位一位。

和它配套的一个细节是：`while` 的条件里一直在用 `stack.back()`，但循环体第一件事就是把它存进 `past` —— 因为**条件判断和循环体读的是同一个值，而循环体会销毁它**。

### 为什么用 `while` 不用 `if`

看主用例下标 2..5 这一段：

```
下标:   2    3    4    5
温度:   75   71   69   72
                    ↑
        读到 72 时，69 和 71 同时等到答案
```

`72 > 69` → 结算下标 4（差 1 天）；弹出后栈顶变成 `71`，`72 > 71` 依然成立 → 结算下标 3（差 2 天）；再弹，栈顶是 `75`，`72 < 75` → 停。

如果这里写成 `if`，只有 `69` 被结算，`71` 的答案就丢了，而且它会**一直留在栈里**，后面被 `76` 结算时算出的距离已经不对了。更糟的是这个错误只在"连续多个下降"的输入上暴露，普通用例很难碰上。

## 坑点

::: warning 坑点
1. **`stack` 存了温度值而不是下标**：`temperatures[stack.back()]` 会直接把温度当数组下标用 —— 温度最大 100，数组长度可能只有 10，**越界读**。就算侥幸不崩，`today - past` 里的 `past` 也变成了温度值，算出的"天数"荒谬。代码里所有 `stack` 的读写都必须明确它装的是下标。

2. **`answer[past] = today` 写成了通用骨架那一版**：这是从模板抄过来时最容易漏的改动。题目要的是**相差几天**，不是"哪一天"。测试用例里 `[73, 74, ...]` 的期望是 `[1, 1, 4, ...]`，写成 `today` 会得到 `[1, 2, 6, ...]` —— 每个值都错，但格式合法。

3. **`while` 条件写成 `>=`**：`temperatures[today] >= temperatures[stack.back()]` 会让**相等**的温度也算作"更高"。`[50, 50, 50]` 的正确答案是 `[0, 0, 0]`（温度没有**升高**），写成 `>=` 会得到 `[1, 1, 0]`。

4. **忘记 `!stack.empty()`**：`stack.back()` 在空 `vector` 上是未定义行为。虽然 `&&` 的短路求值保证了"栈空时不会求值右边"，但这个短路**依赖于 `!stack.empty()` 写在左边**，顺序写反就失去保护。
:::

::: danger 易错
**遍历结束后忘了处理栈里剩下的元素。** 本题里这些元素的答案恰好就是 `0`，而 `vector<int> answer(n, 0)` 已经把它们初始化成 `0` 了 —— 所以**不写任何收尾代码也是对的**。

这很容易让人以为"收尾不需要考虑"，于是在下一题里翻车：如果问的是"右边第一个更小的元素**的值**"，初始值 `0` 并不是合法答案，必须显式填 `-1`；如果是 32 最长有效括号，剩下元素的贡献要单独结算。

写单调栈时养成习惯：**先想清楚"没被弹出的元素，它们的答案是什么"**，再决定初始化值。本题的答案是 0，所以初始化 0 就够；换个问法就不够了。
:::

::: info 补充
**为什么相等元素不弹出？** 本题问"更高"的温度，相等不算。如果题目改成"下一个**不低于**今天的温度"，那就要用 `>=`，相等时也弹出 —— 此时栈变成严格递减，代码只改一个字符。

在处理"下一个更大元素 II"（503 循环数组）时，这个选择会变得关键：`[1,1,1]` 这类全等输入的答案依赖你选的是哪种比较。
:::

## 变体与练习

| 变化 | 改什么 |
|---|---|
| 求下一个更大元素的**值**而非距离 | `answer[past] = temperatures[today]`；剩下元素初始化成 `-1` |
| 求下一个更小元素 | 比较方向反转：`temperatures[today] < temperatures[stack.back()]`（递增栈） |
| 循环数组（503） | 遍历 `2n` 次，下标取 `i % n`，只在 `i < n` 时压栈 |
| 接雨水（42） | 递减栈 + 弹出时用**左右两边的高度差**乘宽度，弹出后还要看新栈顶 |
| 柱状图中最大矩形（84） | 递增栈，哨兵 `0` 压两侧，弹出时 `height[past] * (today - stack.back() - 1)` |
| 滑动窗口最大值（239） | 单调**队列**：除了尾部弹出，还要从头部删掉出窗的元素 |

::: details 为什么 84 题（最大矩形）要在数组两端加哨兵 `0`
因为弹出结算需要**右侧边界**。如果柱子在末尾还保持递增，它们永远不会被弹出，就永远结算不到。在末尾补一个高度 `0` 的柱子，它会比所有元素都小，一次把所有剩余元素全部弹空。

开头补 `0` 是为了让栈**永远不空**，于是 `stack.back()` 在最左边弹出时依然有定义 —— 这正是本题坑点 4 里"栈空弹栈"问题的通用解法：

> **栈空问题，要么用 `empty()` 判，要么用哨兵保证不空。** 后者在 84、42 这类"弹出后还要读新栈顶"的题里几乎是必须的。
:::

单调栈只有两个决定：**栈里存什么**（涉及距离就存下标）和**栈的单调方向**（找更大就用递减栈）。这两个决定定下来，剩下的 `while` 骨架不会有第二种写法。

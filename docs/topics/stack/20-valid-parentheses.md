# 20 · 有效的括号

<ProblemMeta id="20" difficulty="简单" title="有效的括号" :tags="['栈', '配对', '哈希表']" url="https://leetcode.cn/problems/valid-parentheses/" />

::: params 栈与单调栈
| 要素 | 本题取值 |
| --- | --- |
| 栈里存什么 | `stack` 只放"已读入、还没配对"的**左括号**，右括号从不入栈 |
| 入栈前做什么 | 先 `pairs.find(ch) == pairs.end()` 判断它是左括号，`push_back` 后 `continue` |
| 出栈时机 | 右括号到来且 `stack.back() == it->second` 时 `pop_back()`，扫完靠 `return stack.empty()` 判定 |
:::

::: cheat 速查卡
- **什么时候用**：符号有"开/闭"两类，且要求**最近的开**配**最近的闭**
- **核心不变式**：`stack` 里装的全是"已读入、还没被配对"的左括号
- **一句话模板**：遇到左括号压栈；遇到右括号就弹栈顶比对，不匹配或栈空即失败
- **复杂度**：时间 **O(n)**、空间 **O(n)**
:::

## 题意重述

给一个只含 `()[]{}` 的字符串，判断括号是否**合法闭合**。合法的定义包含两条：每个左括号都有同类型的右括号与之配对，且配对不能交叉。

```
输入: s = "()[]{}"
输出: true

输入: s = "(]"
输出: false      ← 类型不匹配

输入: s = "([)]"
输出: false      ← 数量配平但交叉嵌套

输入: s = "("
输出: false      ← 只剩左括号
```

第三个例子是这题的真正考点：**只数个数是过不了的**。`([)]` 里小括号一对、方括号一对，数量完全平衡，但它不合法 —— `)` 必须关掉它左边**最近的那个**还没配对的左括号，而那个位置上是 `[`，不是 `(`。

## 从朴素到最优

最朴素的想法是计数：记 `(` 的个数、`)` 的个数，最后相等就算合法。这个做法在 `([)]` 上直接错，因为计数完全丢掉了**顺序**和**类型嵌套**信息。

第二个想法：反复扫描，把出现的 `()`、`[]`、`{}` 就地删掉，删不动了再看剩下的是不是空串。这是**正确的** —— `([)]` 第一轮找不到连续合法对，剩下的还是原串，判错；`([])` 删掉 `[]` 后剩下 `()`，再删一轮就空了。

但它每轮都要重扫一遍全串，最坏 O(n²)，而且"删掉中间两个字符"本身要搬移数据。

关键转折只有一句：

> **"删掉一对相邻的合法括号" 和 "遇到右括号时弹出栈顶" 是同一个操作。**

被删掉的那对，其右括号的左边第一个字符，恰好就是当时"最近一个还没配对的左括号"。既然每次关心的都是**最近的那个**，那就用栈。栈把这个操作从"在字符串里找位置"变成"看一眼尾部"，O(1)。

## 模板对照

::: compare 配对型栈骨架 | 20 本题：哈希表定配对
```cpp
// 通用骨架：压栈 -> 遇终止符弹栈比对
for (char ch : s) {
    if (isOpen(ch)) {
        stack.push_back(ch);
        continue;
    }
    // 弹之前必须判空
    if (stack.empty())
        return false;
    if (stack.back() != want(ch))
        return false;
    stack.pop_back();
}
return stack.empty();
```
```cpp
// 本题：用哈希表回答"它要哪个左括号"
unordered_map<char, char> pairs{
    {')', '('}, {']', '['}, {'}', '{'}
};

for (char ch : s) {
    auto it = pairs.find(ch);
    if (it == pairs.end()) {
        stack.push_back(ch);   // 是左括号
        continue;
    }
    if (stack.empty())
        return false;
    if (stack.back() != it->second)
        return false;
    stack.pop_back();
}
return stack.empty();
```
:::

两栏的差别只在 `isOpen` 和 `want` 这两个函数怎么实现。本题字符集固定成六个符号，所以最省事的写法是**一张三行的哈希表**：拿右括号当 key 查，查得到就是右括号、值是它要的左括号；查不到就一定是左括号。

::: info 补充
`isOpen(ch) / want(ch)` 这两个函数也可以写成两个 `switch`，或两个 `string::find`。用 `unordered_map` 的好处是把"配对关系"变成**数据**而不是**分支**：以后加一对 `<>`，只往初始化列表里加一项，判断逻辑一行都不用动。

另一种等价写法是**反向表**：键放左括号（`'(' -> ')'`），遇到右括号时先判空，再检查 `pairs[stack.back()] == ch`。两种都行，但 `pairs[stack.back()]` 用的是 `operator[]`，key 不存在时会**静默插入一个空值**（`'\0'`）—— 好在本题里栈中只可能是三种左括号，不会触发。本题用"右括号做 key + `find`"，天然避开了这个隐患。
:::

### 一个 O(1) 剪枝：奇数长度

任何合法括号串都是**成对**出现的，所以长度必然是偶数。

```cpp
if (s.size() % 2 == 1) return false;
```

这行加在函数最前面，省掉后面所有工作。它不改变复杂度（还是 O(n)），但把"长度 3 的 `(((`"这类必然失败的输入挡在门外。

注意它**只挡奇数长度**：五万个左括号是偶数长度，剪枝挡不住，仍要扫完整个串、靠 `stack.empty()` 判定。

::: tip 提示
剪枝是**优化，不是正确性来源**。删掉这行代码，答案依然全对 —— 只是奇数长度的串会在扫完之后靠 `return stack.empty()` 得到 `false`。写题解时把它当成"顺手赚的"，不要把它讲成"必须有"。
:::

## 完整可编译代码

```cpp
#include <cassert>
#include <iostream>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    bool isValid(const string& s) {
        // 奇数长度不可能两两配对
        if (s.size() % 2 == 1) return false;

        // 右括号 -> 它要求的左括号
        const unordered_map<char, char> pairs{
            {')', '('}, {']', '['}, {'}', '{'}
        };

        vector<char> stack;              // 栈里只放"还没配对的左括号"
        stack.reserve(s.size());

        for (char ch : s) {
            auto it = pairs.find(ch);
            if (it == pairs.end()) {     // 是左括号，压栈等配对
                stack.push_back(ch);
                continue;
            }
            // 是右括号：栈空说明没有左括号和它配对
            if (stack.empty()) return false;
            // 栈顶不是它要的那个左括号
            if (stack.back() != it->second) return false;
            stack.pop_back();            // 配对成功，弹出
        }

        // 全部扫完，栈必须为空；否则剩下的左括号无右括号可配
        return stack.empty();
    }
};

int main() {
    Solution sol;

    assert(sol.isValid("()") == true);
    assert(sol.isValid("()[]{}") == true);
    assert(sol.isValid("(]") == false);
    assert(sol.isValid("([])") == true);
    assert(sol.isValid("([)]") == false);   // 交叉嵌套，不是合法的
    assert(sol.isValid("") == true);        // 空串：栈空，返回 true
    assert(sol.isValid(")(") == false);     // 偶数长度：第一个字符就栈空弹栈
    assert(sol.isValid("()][") == false);   // 偶数长度：扫到 ']' 时栈空
    assert(sol.isValid("{[]}") == true);
    assert(sol.isValid("((") == false);      // 偶数长度、多一个左括号
    assert(sol.isValid("()((") == false);    // 同样是偶数长度，剪枝拦不住
    assert(sol.isValid("(((") == false);     // 奇数长度，剪枝直接返回
    assert(sol.isValid("{{{[[[((())))]]]}}") == false);  // 偶数长度，剪枝拦不住
    assert(sol.isValid(string(50000, '(')) == false);

    cout << "all tests passed" << endl;
    return 0;
}
```

用 `vector<char>` 当栈而不是 `std::stack<char>`，是因为 `stack` 适配器没有 `reserve`，也不支持按下标访问；而 `vector` 的 `push_back` / `back` / `pop_back` 恰好就是全部需要的东西，还多了内存连续这个好处。

`main` 里 14 个断言按失败模式分组：合法（`()`、`()[]{}`、`([])`、`{[]}` 四个形态）、类型不符（`(]`）、交叉嵌套（`([)]`）、栈空弹栈（`)(`、`()][`）、扫完不空（`((`、`()((`）、空串、奇数长度（`(((`）、深层配对错（18 字符）、以及一个 5 万字符的长串（验证 `reserve` 之后没有性能问题）。

`"((("` 是唯一会被第一行剪枝直接 `return false` 的用例，**走不到**它看起来要测的分支 —— 这不是缺陷，而是本页要讲的重点：剪枝会把"看起来在测某分支"的用例悄悄吞掉。所以覆盖"栈空弹栈"和"扫完不空"的用例必须全是**偶数长度**，代码里那 4 条就是专门为此写的。

## 逐段拆解

::: semantics
| 字段 | 含义 | 在代码里怎么用 |
| --- | --- | --- |
| `stack` | 存"已读入但还没被配对"的**左括号**，只存左括号 | 右括号永远不入栈，它只负责触发弹出和判错 |
| `pairs` | 右括号 → 它要求的左括号 | 一张静态表，把配对关系变成数据 |
| `it == pairs.end()` | 当前字符**不是**右括号 | 那就是左括号，压栈后 `continue` |
| `it->second` | 当前右括号要求的左括号类型 | 拿它和 `stack.back()` 比，不是和整个栈比 |
| `stack.back()` | **最近一个**还没配对的左括号 | 括号嵌套的语义就落在这一个位置上 |
| `stack.empty()`（循环内） | 右边多出来了 | 立刻 `return false`，不能先 `back()` |
| `stack.empty()`（返回处） | 左边有没有多出来 | 空则全部配平，非空则剩下的是多余的左括号 |
:::

### 为什么"栈最后必须为空"是充分必要条件

这句 `return stack.empty()` 不是顺手加的保险，它是正确性的一半。把失败拆开看，只有三种：

| 失败情形 | 例子 | 在哪里被拦下 |
|---|---|---|
| 右括号比左括号多 | `")("` | 循环内的 `stack.empty()` 分支 |
| 类型不匹配（含交叉嵌套） | `"(]"`、`"([)]"` | `stack.back() != it->second` |
| 左括号比右括号多 | `"(("` | 返回处的 `stack.empty()` |

注意上表"例子"列必须是**偶数长度**：`"("`（长度 1）会在奇偶剪枝那一行就被挡掉，根本走不到它对应的分支。

**必要性**：如果扫完栈非空，栈里的每个元素都是"读入过、但从没被弹出"的左括号，它们没有右括号配对，所以串不合法 —— 必须返回 `false`。

**充分性**：如果扫完栈为空，说明每一个右括号在被读到时，都成功地在栈顶找到了匹配的左括号并被弹出。而"弹出栈顶"这个动作恰好对应"配给最近的那个未配对左括号"，所以所有配对都不交叉。再加上栈空保证了没有剩余左括号，整个串合法。

注意最后一行的表达式 `return stack.empty();` **直接返回布尔值**，不要写成 `if (stack.empty()) return true; return false;` 之类的分支 —— 前者一句话就说清了"合法 ⟺ 栈空"。

### 为什么只比栈顶，不比整个栈

`([)]` 这个例子值得单独走一遍：

```
读 '('  → stack = [ ( ]
读 '['  → stack = [ ( [ ]
读 ')'  → 要求 '('，栈顶是 '['  → false
```

如果实现成"在栈里找有没有 `(`"，这个用例就会被误判为 `true`。括号的嵌套是一种**后进先出**的结构：`)` 只能关掉它左边最近的、还没被关掉的 `(`，中间不允许夹着别的未闭合括号。所以判断依据只能是**栈顶**，不能是"栈里存在"。

## 坑点

::: warning 坑点
1. **`stack.empty()` 必须写在 `stack.back()` 之前**：`")"` 进来时栈是空的，`stack.back()` 在空 `vector` 上是**未定义行为**（常见表现是读到垃圾值，或者 `size() == 0` 时 `size() - 1` 回绕成巨大下标直接段错误）。代码里这两行是紧挨着的两个 `if`，顺序不能交换。

2. **`{')', '('}, {']', '['}, {'}', '{'}` 写反了方向**：键必须是**右**括号。写反成 `{'(' , ')'}` 后，`pairs.find('(')` 会命中，于是左括号被当成右括号处理 —— 所有用例全错，但类型检查不会报任何问题。

3. **`stack.back() != it->second` 拿错了比较对象**：`it->second` 是"要求什么"，`stack.back()` 是"实际是什么"，写反了（`it->second != stack.back()`）结果一样，但如果写成 `ch != it->second`（拿右括号和左括号比）就永远为真，于是每个右括号都被判错、整个函数恒返回 `false`。

4. **`s.size() % 2` 的返回类型**：`s.size()` 是 `size_t`（无符号），`% 2` 得到 `0` 或 `1`，写成 `if (s.size() % 2)` 是安全的。但如果写成 `int rest = s.size() % 2;` 再和 `-1` 比较之类的操作，无符号数的回绕会咬人。这类比较统一加 `static_cast<int>` 或直接判断。
:::

::: danger 易错
**把返回处的 `return stack.empty()` 写成 `return true`**，这是本题最典型的静默错误。`"("`、`"(("`、`"()(("` 这类"左括号多出来"的用例会全部返回 `true`，不崩溃、不报错，只是答案错。

更麻烦的是：这个 bug **只在偶数长度的输入上暴露**。`"((("`（长度 3）会被前面的奇数剪枝直接挡掉，`"("`（长度 1）也一样 —— 你在自测时随手写几个"括号没配完"的用例，很可能全被剪枝吞掉，看起来一切正常。

所以：**测这个 bug 必须用偶数长度的多余左括号**，比如 `"(("` 或 `"()(("`。代码里 `assert(sol.isValid("((") == false)` 和 `assert(sol.isValid("()((") == false)` 两行就是专门为它写的。
:::

## 变体与练习

| 变化 | 改什么 |
|---|---|
| 只有一种括号 `()` | 去掉哈希表，`stack` 里可以只存一个 `int count`（因为唯一类型，栈内元素全相同） |
| 允许 `*` 代表任意括号（678 有效的括号字符串） | 单栈不够，需要**双栈**（左括号栈 + 星号栈）或贪心双向扫描 |
| 求最长有效括号子串（32） | 栈里存**下标**而非字符，栈底压 `-1` 当基准；弹完若栈空就把当前位置压入当新基准，否则用 `i - stack.back()` 更新答案 |
| 给出所有合法组合（22 括号生成） | 不再是判定，改成回溯：记录 `used_left` / `used_right`，只在 **`used_right < used_left`** 时放右括号 |
| 判断 HTML 标签闭合（如 `<div></div>`） | 每个标签是**变长的**，先把标签名解析成字符串再压栈，比对的是字符串而非单字符 |

::: details 为什么 32 题（最长有效括号）要存下标
因为那题问的是**长度**，不是"是否合法"。一旦需要长度，就必须知道每个位置在哪儿 —— 字符栈只能告诉你"配对成功了"，不能告诉你"这一对跨了多少个字符"。这和 [739 每日温度](/topics/stack/739-daily-temperatures) 里"存下标而不是存值"是同一个理由：

> **只要答案需要"距离 / 位置 / 长度"，栈里就必须存下标。**

本站把这条规则当成单调栈和配对栈的公共常识，后面的题会反复用到。
:::

配对型问题的代码只有三行是"活的"：**左括号压栈、右括号比栈顶、最后看栈空**。其余都是这三行的包装。写的时候先默念一遍这三行，再去处理边界。

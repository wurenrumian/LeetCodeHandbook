# 双指针 · 模板与变体

双指针不是一种算法，是**一种把两重循环压成一重的技巧**。判断能不能用的核心问题：

> 两个指针的移动方向，能不能各自**单调**？如果算完一次之后能确定"某个指针一定不用回头"，复杂度就从 O(n²) 降到 O(n)。

## 三种双指针

它们的骨架长得很像，但**为什么正确**完全不同。混着用是最常见的失分点。

| 类型 | 指针关系 | 正确性来源 | 代表题 |
|---|---|---|---|
| 对撞指针 | `left` 右移、`right` 左移，直到相遇 | 有序性 + 排除法 | 167 两数之和 II |
| 快慢指针 | 同向，`fast` 快于 `slow` | 相对速度/位置差 | 26 去重、141 环形链表 |
| 分离双指针 | 各自扫各自的序列 | 归并思想 | 88 合并两个有序数组 |

## 对撞指针模板

<!-- #region template-1 -->
```cpp
int left = 0, right = n - 1;
while (left < right) {          // 不是 <= ，因为不能取同一个元素
    int sum = nums[left] + nums[right];
    if (sum == target) return {left, right};
    if (sum < target) ++left;    // 和太小 → 需要更大的数 → 左指针右移
    else              --right;   // 和太大 → 需要更小的数 → 右指针左移
}
```
<!-- #endregion template-1 -->

**为什么能排除**：数组升序时，`nums[left] + nums[right] < target` 说明 `nums[left]` 和**任何** `nums[j]`（`j <= right`）配对都不够大 —— 因为 `nums[right]` 已经是能配到的最大值。所以 `left` 这个位置彻底作废，可以扔。

这个"扔"的动作，就是对撞指针的全部。

::: warning 坑点
对撞指针**强依赖有序性**。如果数组无序，`sum < target` 完全推不出"左指针该右移" —— 右边可能还有更大的数。两数之和（1 题）返回下标、不能排序，所以它必须用哈希而不是双指针。
:::

## 快慢指针模板（原地修改）

<!-- #region template-2 -->
```cpp
int slow = 0;                       // 写指针：下一个"有效元素"该放的位置
for (int fast = 0; fast < n; ++fast) {   // 读指针：扫描全部元素
    if (/* nums[fast] 是有效元素 */) {
        nums[slow] = nums[fast];    // 写到前面
        ++slow;
    }
}
// [0, slow) 是结果
```
<!-- #endregion template-2 -->

理解它的关键在于**两个指针的角色不是"左右"，而是"读"和"写"**：

- `fast` **只读**，负责检查每个元素
- `slow` **只写**，负责维护"已确认结果"的边界

`slow <= fast` 恒成立，所以 `nums[slow] = nums[fast]` 永远不会覆盖还没读的数据。这是它安全的原因。

### 区间约定

快慢指针里最容易错的是"返回值到底是 `slow` 还是 `slow + 1`"。取决于你的不变式怎么写：

| 不变式 | 结束时 | 返回 |
|---|---|---|
| `[0, slow)` 是结果 | `slow` 是结果长度 | `slow` |
| `[0, slow]` 是结果 | 结果是 `slow + 1` 个 | `slow + 1` |

**先写下不变式，再写返回语句。** 反过来做，一定会差一。

## 变体索引

### 变体 1：去重（[26](/topics/two-pointers/26-remove-duplicates)）

有效元素 = "和上一个保留的元素不同"。`slow` 从 1 开始（第一个元素天然保留）。

### 变体 2：移除元素（27）

有效元素 = "不等于 val"。`slow` 从 0 开始。

```cpp
int slow = 0;
for (int fast = 0; fast < n; ++fast)
    if (nums[fast] != val) nums[slow++] = nums[fast];
return slow;
```

对比 26 题：**去重的 `slow` 从 1 起步，移除元素的从 0 起步。** 差别在于"第一个元素是否需要判断"。

### 变体 3：移动零（283）

有效元素 = "非零"。本质和 27 题一样，且**必须保持相对顺序**。交换和覆盖两种写法都保序，也都不需要额外空间：

```cpp
// 覆盖式：末尾要手动补零
int slow = 0;
for (int fast = 0; fast < n; ++fast)
    if (nums[fast] != 0) nums[slow++] = nums[fast];
fill(nums.begin() + slow, nums.end(), 0);

// 交换式：不用补零
int slow = 0;
for (int fast = 0; fast < n; ++fast)
    if (nums[fast] != 0) swap(nums[slow++], nums[fast]);
```

交换式能保序的原因是：`slow` 永远落在**第一个 0** 上，被换出去的恰好是 0（`slow == fast` 时是换自己）。两种写法都正确，选一种即可。

### 变体 4：三数之和（15）

排序 + 固定一个数 + 对撞指针。去重要点：**固定数、`left`、`right` 三处都要跳重复**。

### 变体 5：环形链表（141）

不是数组双指针，但同属快慢思想：`fast` 每次走两步，`slow` 一步。有环时 `fast` 一定会追上 `slow`（相对速度 1），最多 `n` 步。

## 坑点汇总

::: warning 坑点
1. **`while (left <= right)`**：对撞指针取同一个元素是错的（等于同一个数用两次）。除非题目允许，否则用 `<`。

2. **快慢指针返回差一**：先定不变式 `[0, slow)` 还是 `[0, slow]`。

3. **`slow` 和 `fast` 写反**：`nums[fast] = nums[slow]` 会把已确认的元素覆盖掉。记住 `fast` 是读、`slow` 是写。

4. **忘记空数组**：`n == 0` 时 `slow = 1` 会返回 1，实际应为 0。去重题必须特判。
:::

## 自检清单

- 移动某个指针时，能说出"这个位置为什么彻底作废"吗？
- 谁读、谁写，写指针会不会越过读指针？
- 不变式是 `[0, slow)` 还是 `[0, slow]`？返回值与之匹配吗？

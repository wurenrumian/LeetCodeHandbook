# 这份手册怎么用

这是一个**本地内网站点**，内容全部是静态 Markdown，构建后 `docs/.vitepress/dist/` 直接丢到内网 nginx 就能访问。

## 它和其他题解的区别

大多数题解讲的是"这题的解法是什么"。这份手册假设你已经看过解法，真正卡住你的是下面这些：

- `left = mid + 1` 和 `left = mid` 到底什么时候用哪个？
- `dp[i]` 里的 `i` 是"金额"还是"物品下标"？为什么这题可以这么定？
- `while (l < r)` 和 `while (l <= r)` 差在哪，改一下会死循环吗？
- 滑动窗口里 `l` 是"窗口左端"还是"第一个不合法位置"？

所以每一页的结构是固定的：**先给模板，再看这题改了哪几行，最后逐段拆字段语义，收在坑点上。**

## 三种页面

| 页面 | 位置 | 作用 |
|---|---|---|
| 专题总览 | `/topics/<专题>/` | 该算法族的统一模板 + 变体索引 + 适用信号 |
| 题目精讲 | `/topics/<专题>/<题号>-<slug>` | 单题：模板对照 → 完整代码 → 字段语义 → 坑点 |
| 题目索引 | `/problems/` | 按难度/专题/标签筛选的全量题目表 |

## 每页的固定结构

题目精讲页从上到下永远是这个顺序，熟练后可以跳读：

::: cheat 速查卡
- **什么时候用**：什么信号出现时该想到这个算法
- **核心不变式**：循环/递归全程为真的那句话
- **一句话模板**：背下来就够用的骨架
- **复杂度**：时间 / 空间，以及为什么
:::

1. **题意重述** — 用输入输出说话，不用题目原文
2. **模板对照** — 通用模板 vs 本题代码，标出改动的行
3. **完整可编译代码** — 只 include 真正用到的头文件，带 `main`，`clang++ -std=c++17` 或 `g++ -std=c++17` 直接跑
4. **逐段拆解** — `::: semantics` 表逐字段解释含义
5. **坑点** — `::: warning`，每条对应代码里一个具体位置
6. **变体与练习** — 改了条件后模板要怎么动

## 这个站点不记你的任何东西

没有登录，没有刷题进度，没有测评。站点是纯静态的 Markdown，你读到的东西对谁都一样，也不会因为你换了浏览器而消失。

理由很简单：**模板、字段语义、边界坑点是不随时间变化的**，适合做成可以反复查、可以 grep、可以 diff 的文档；而"我今天练到第几题"是随时在变的状态，需要登录、存储、同步——那是另一个产品的事，不该混进来。

## 怎么开始

- 想系统过一遍：从 [专题总览](/topics/) 按顺序读
- 想补某个弱点：直接去 [题目索引](/problems/) 筛标签
- 想加题：先读 [写作与代码约定](/guide/conventions)，里面有代码风格和模板写法
